# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

OPA2000 is a ham radio power amplifier controller based on STM32H7B0VBT6 MCU. It controls a 200W+ HF amplifier with band switching, power/vswr monitoring, multi-language GUI, and PC/radio communication interfaces.
## Coding Rules
The qualifier 'extern' should only appear in header files. No 'extern ' in .c files.

### LVGL String Lifetime (CRITICAL)
LVGL v7 stores **pointers** to strings, it does **NOT** copy them. This applies to:
- `lv_label_set_text()` / `lv_label_set_text_static()` — stores a pointer to the text buffer
- `lv_btnmatrix_set_map()` — stores the pointer to the entire button-text array
- `lv_msgbox_add_btns()` → internally calls `lv_btnmatrix_set_map()`

Therefore ALL string data passed to these functions must outlive the widget:
- **Use `static` arrays** for button maps, msgbox button labels, etc.
- Stack-local arrays will produce dangling pointers → **crash on click or redraw**
- String literals (`"foo"`) are always safe (they live in .rodata)

### LVGL Simulator Mode
When adding GUI code, wrap OPA2000 hardware dependencies with `#ifndef LVGL_SIM`. Use placeholder text/values in the `#else` branch. The `LVGL_SIM` flag (set in CMake with `-DLVGL_SIM=ON`) enables compilation in an external LVGL v7 emulator without any OPA2000 control logic. Files to guard: `#include "main.h"`, HAL handle externs in headers, and any code accessing OPA2000 globals (`g_config`, `g_adc_data`, `g_power_state`, `g_current_band`, etc.) or calling OPA2000 functions (`power_on/off`, `config_save`, `touch_calibrate_start`, etc.).

### Multi-language GUI Rules (gui.c)

**Font**: All user-visible text that CAN contain Chinese must use CJK font (`&MyCJK_16`). Montserrat is only safe for guaranteed-English content (numeric values like `"0W"`, `"1.0"`, frequency ranges like `"7.000-10.150 MHz"`, radio mode names like `"ICOM"`).

**Adding a new string** (3-step checklist):
1. Add a `STR_xxx` entry to the `enum` at top of `gui.c`
2. Add Chinese and English strings in the corresponding positions in `gui_strings[2][30]`
3. If it's a label that persists on screen (not a popup), add `{&your_label, STR_xxx}` to the `lang_refresh[]` array near `gui_set_language()`

**Language refresh array**: `LangRefreshEntry lang_refresh[]` holds all labels that need text update when `gui_set_language()` is called. The one-line-per-entry format is intentional — no long `if`/else blocks.

## Important Architecture Notes

### Code Organization
- **User code goes in `./User` directory** - this is the only directory where you may create or modify source files
- Other directories are auto-generated by CubeMX and must not be manually edited
- Use HAL APIs exclusively; avoid direct register manipulation
- Only the ./User/USB_DEVICE folder is valid, the USB_DEVICE folder outside is auto gen by CubeMX, which is deprecated

### Memory Layout
- **LVGL framebuffer**: Partial buffer, 1/5 screen height (~153KB)
- **LTDC framebuffer**: Full 480x800x16bit buffer (~768KB) - must be placed in specific SRAM region with `__attribute__((section(".framebuffer")))` or similar

### Key Hardware Interfaces
- **ADC**: 8 channels via 2 ADC units (continuous scan mode with DMA) - transmit power 1/2, reflected power 1/2, voltage, current, NTC temperature, detector sample
- **USB CDC** + **LPUART1**: Shared RX/TX data queue for PC communication (default 19200 baud)
- **USART1**: Radio communication (ICOM CIV, Yaesu, Kenwood formats auto-detection)
- **I2C1**: EEPROM (AT24C02) for config storage, capacitive touch (GT911)
- **SPI1**: Resistive touchscreen (TCS2046)
- **LPTIM1**: Rotary encoder counter
- **PWM outputs**: Fan control (10KHz), buzzer

### Protection System
- External interrupts (HARDPWR_ERR, COMP1, COMP2, Overdrive) have higher priority than FreeRTOS
- Do NOT call FreeRTOS APIs from these ISR handlers
- Use flag variables to communicate with GUI task

## Configuration

All configurable parameters are marked with `[config]` in the documentation. Config is stored in EEPROM (AT24C02) and includes:
- PC communication baud rate
- Radio type and baud rate
- Power protection thresholds (400W reflect, 200W+2.0 SWR, 600W reflect, 40A current)
- Touchscreen calibration parameters
- Directional coupler calibration data

## Coding Standards
- Comments in English
- User display text supports bilingual (Chinese/English) - maintain language structure for easy translation
- Commit git changes locally after significant improvements (do not push)

## Important Notes

### Vector Table Relocation (IMPORTANT)

After each CubeMX regenerate, check and restore vector table relocation in `Core/Src/system_stm32h7xx.c`:

1. Add `#include <string.h>` at the top
2. Add vector table buffer definition before `SystemInit()`:
   ```c
   /* Vector table buffer in ITCMRAM for fast interrupt response */
   static uint8_t __attribute__((section(".isr_vector_ram"))) isr_vector_ram[0x400];
   ```
3. Add relocation code at the end of `SystemInit()`:
   ```c
   /* === User added: Vector table relocation to ITCMRAM === */
   const uint32_t addrExtFlash = 0x90000000;
   memcpy((void*)isr_vector_ram, (void*)addrExtFlash, sizeof(isr_vector_ram));
   SCB->VTOR = (uint32_t)isr_vector_ram;
   /* ====================================================== */
   ```

Also ensure `STM32H7B0XX_FLASH.ld` has the `.isr_vector_ram` section:
```ld
.isr_vector_ram (NOLOAD) : ALIGN(4)
{
    . = ALIGN(4);
    _isr_vector_ram_start = .;
    KEEP(*(.isr_vector_ram))
    . = ALIGN(4);
    _isr_vector_ram_end = .;
} >ITCMRAM AT> EXT_FLASH
```
