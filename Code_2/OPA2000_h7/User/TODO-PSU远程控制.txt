三、硬件事实（已核实，不要凭直觉写反极性）
--------------------------------------------------------------------------------
  PSU = Power Supply Unit，是**外部设备**，PG5 只是 MCU 进去的控制线。

      PG5 ──> NPN Q9（反相）──> PC13 = PWR_WKUP4

  Q9 反相，所以**从 MCU 的 GPIO 视角**看极性是「高电平开机」：

      PG5 高 → Q9 导通 → PC13 拉到 GND   → PSU 开机
      PG5 低 → Q9 截止 → PC13 回到上拉   → PSU 关机

  这与设计要求 6 节和 hw_pinmap.h 的 PSU_ON_PWR_ON/PSU_ON_PWR_OFF 一致。
  ⚠ 别按"低有效"的直觉写反 —— 板上是反相的，MCU 侧看是高有效。

四、协议待定项（需要你确定后我才好把开关打开）
--------------------------------------------------------------------------------
  □ 走 ASCII 行协议（跟现有的 STATUS / SET FREQ 同一套）还是二进制包？
  □ 关键字怎么写？候选：
        "PSU ON" / "PSU OFF"        与现有 SET FREQ 风格一致
        "PSU 1" / "PSU 0"            更短
        "POWER ON" / "POWER OFF"     但 POWER 可能与高压按钮混淆，不建议
  □ 要不要回读查询命令（"PSU?"），以便确认当前状态？
  □ 返回什么字符串？现在骨架里写的是 "PSU ON" / "PSU OFF"，
    出错是 "ERROR: PSU control not implemented"，要不要统一格式？
  □ 远控开机是否需要与本地联锁（g_allow_rf / g_alert_flag）一致？
    即：保护告警锁存中收到 "PSU ON" 要不要拒绝？
    现在的骨架是**不拒绝**的（power_psu_on() 本身不带联锁）。
  □ 是否需要软启动（PSU 上电后等电压稳定再允许上高压）？
    如果需要，要加一个 g_psu_settled 之类的标志 + 延时状态机，
    这会影响 power_hv_enable() 该不该检查它。
