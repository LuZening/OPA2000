[4] 【需确认】.framebuffer 的物理地址要和 LTDC FBStartAdress 一致
------------------------------------------------------------------------
现在的写法：
  lv_port_disp.c 里用数组名取址：
      static uint16_t __attribute__((section(".framebuffer")))
          ltdc_framebuffer[480*272];
  链接脚本把 .framebuffer 放在 RAM 的哪个位置，
  LTDC 的 FBStartAdress 就必须填那个绝对地址。

CubeMX 默认给的是 0x24000000，但那段 RAM 起始处通常还有别的用途，
所以两者很可能对不上。

两种做法（选一种）：
  方案A（推荐，不用改 ioc）：
    在链接脚本里加一个导出符号，然后在 ltdc.c 的
    /* USER CODE BEGIN LTDC_Init 2 */ 里写：
        extern uint32_t _framebuffer_start;
        hltdc.LayerCfg[0].FBStartAdress = _framebuffer_start;
    这样地址永远跟着链接结果走，不会错。

  方案B：
    手工算好 .framebuffer 在 RAM 里的偏移，
    把这个绝对值填进 ioc 的 LTDC layer 配置里。

[已解决] 9. peak 变量 —— Control 已实现，GUI 可直接用
    变量名沿用你定的，已在 User/Inc/opa2000.h 的 AdcDataType：

        volatile int32_t fwd2_peak_mW;   /* 耦合器2 发射功率峰值, 毫瓦 */
        volatile int32_t rev2_peak_mW;   /* 耦合器2 反射功率峰值, 毫瓦 */

    swr_x100 仍是瞬时值，你用两个 peak 现算 SWR 的做法照旧可行：
        calculate_swr_x100(fwd2_peak_mW, rev2_peak_mW)

    算法（你说由我决定）：
        out[n] = max(sample[n], out[n-1] × exp(-dt / tau))
        tau = 500 ms
      · attack 瞬时：新值更大立刻跳上去
      · release 指数：500ms 后剩 36.8%，1.5s 后剩 5%，5s 后剩 0.67%
      · 已改用 float + expf()，不再是定点数

    ★ 与上一版不同的两点，请注意 ★

    (1) 完全不受按键 / g_tx_active 影响。
        peak 表是"仪器读数"，客观反映耦合器测到的东西，不是按键状态的
        函数：
          · 空闲时读数为 0，peak 自己按 tau 淡出到 0；
          · 空闲时读数非 0（前端噪声/耦合器故障/外部漏进来的 RF），
            就如实显示出来 —— 这正是操作员需要看到的，不该被藏起来。
        上一版做的"按键上升沿清零""未按键不采样"都已删除，因为那会让
        读数在跟射频无关的时刻跳变，反而不是客观反映。

    (2) 驱动函数换了，请不要在中断里调用：
            void adc_peak_hold_tick(void);
        由 ADC task（app_tasks.c，50ms）调用一次。
        原因：adc_process() 同时挂在 ADC1 DMA 完成中断（主优先级 0）上，
        而 release 需要 expf()。把 peak 放在 task 里跑，优先级 0 的中断
        就不会碰 libm 和 FPU。
        adc_process() 本身仍会照常在中断里跑（那是保护判定需要的），
        它只负责更新瞬时值 fwd2_mW / rev2_mW。

    写入方：只有 User/Src/user_adc.c。
    读取方：GUI。请勿写这两个字段。

    测试：User/Tests/test_user_adc.c 里 14 个 peak 用例，其中专门覆盖
    "按键状态不影响结果""按键跳变不清零""空闲非零读数如实显示"
    "中断/task 两种发布节奏结果一致"。

    另外提醒：ConfigType 字段名/类型上轮被 Control 改过（见下面第 [2]
