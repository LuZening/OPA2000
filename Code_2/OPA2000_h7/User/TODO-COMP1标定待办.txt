一、为什么卡住
--------------------------------------------------------------------------------
COMP1 的作用是 RF 输入过驱保护：COMP1 正输入 = PB2 = ADC1_INP4 (PC4) 同节点，
即 RF1 经 D5/R40 峰值检波后的直流电平；负输入 = DAC1_OUT1（由软件写 DAC 码
产生参考电压）。比较器在 PB2 > DAC 参考电压时触发保护。

DAC 能算的部分是确定的（见下方「已确定」），但「DAC 参考电压 ↔ 多少瓦」这一步
缺少实测斜率，原因如下：

  设计要求文档 408 行原文：
    int32_t adc1_raw_to_rf_in_mW(uint16_t raw)
    // [0] RF 输入功率（D5/R40 峰值检波，无耦合器），单位 mW，
    //     暂用上述曲线，实测偏差大时另加修正系数

  也就是说 adc1_raw_to_rf_in_mW() 目前套用的是 OPA1000 的定向耦合器模型：
      DC_TURNS = 33, DC_ATTEN_RATIO = 4.3, Vf(BAT54) = 300mV, Z0 = 50Ω
      VRF = (Vadc + Vf) × 4.3 × 33
      P(W) = VRF² / 50 / 2          → 满量程约 1400W

  但 COMP1 前面根本没有定向耦合器，只有 D5 + R40 峰值检波器。该模型的匝数比
  (×33) 和衰减比 (×4.3) 在这条链路上完全不存在。文档作者自己也标注了
  「暂用」「实测偏差大」。

  用这套错位模型反算 20W：
      vrf = √(20000mW × 100000) = 44721 mV
      Vadc = 44721 × 10 / 1419 - 300 = 15.16 mV
      DAC 码 = 15.16 / 3300 × 4095 = 19
  20W 只落到 DAC 码 19（满量程 4095 的 0.46%）。若 D5/R40 的实际衰减比与
  模型相差 N 倍，真实门限就会偏离 20W 达 N 倍 —— 对一台 1100W 功放，
  这个误差直接决定 COMP1 是保护还是误动作。

二、需要你提供的实测数据（台架标定）
--------------------------------------------------------------------------------
标定方法（最省事的一种）：
  1. 信号源给 RF1 输入一个已知功率 P_in（如 5W / 10W / 20W / 30W，50Ω 匹配）
  2. 万用表测 PB2 对地直流电压（COMP1_INP 同节点），记为 V_meas(P_in)
  3. 拟合出斜率 K，单位 mV/W
     K = ΔV / ΔP     （建议取 5W~25W 区间做线性拟合，避开检波死区）

需要回填给开发者的数据：
    D5/R40 检波链斜率 K = ______ mV/W
    检波死区（低于多少 mV 时输出为 0）= ______ mV
    线性度确认：5W~25W 区间是否严格线性？ Y / N
    若非线性，给出 3 个以上 (P, V) 实测点：______

三、标定完成后的固件改动（届时再执行，现在不做）
--------------------------------------------------------------------------------
方案：config 增加 comp1 斜率字段，UI 同时显示 W 和 mV
    新增 config 字段：comp1_mv_per_watt  (uint16_t，单位 0.1 mV/W)
    DAC 参考电压计算：
        comp1_ref_mV = comp1_mv_per_watt / 10 × 目标功率(W)
    在 DAC 上限处钳位（不超过 COMP1_REF_MV_MAX）
    这样用户在 GUI 调「RF 输入过驱门限（瓦）」，内部自动换算成 DAC 码，
    既符合使用习惯，又没有硬编码。

四、当前（标定前）采取的保守策略
--------------------------------------------------------------------------------
COMP1 的 config 默认值 comp1_ref_mV = 1500 mV，理由：
    - 1500mV ≈ DAC 满量程(3300mV) 的 45%
    - 远高于检波器噪底，保证不会因噪声误触发
    - 也就是说：在你标定之前，COMP1 只会在明显异常的大信号时才动作，
      它是一道「兜底」，不承担精确门限的职责
真正的精确门限由 AWD1（ADC1_INP4 看门狗，软件阈值 band_rf_in_max_w[]，
10~20W 按波段）承担 —— AWD1 是数字比较，不依赖 DAC 精度。

五、附：COMP2 不受此阻塞（链路已确定）
================================================================================
COMP2（PE9 / 主电流 IM）不需要标定，因为 CC6920BSO-50A 的传递函数在设计
要求 219 行已给定：

    Vout_mV = 1650 + I_A × 26.4

信号链：H1-3 IM_SENSE → R111 → U20-B (GS8552-SR, pin5/6/7) 缓冲 → PE9/COMP2_INP
U20-B 是电压跟随器（增益 1），所以 COMP2 引脚电压 = CC6920 输出电压。

对应关系（本次已实现的部分）：
    门限 20A → 2178 mV → DAC 码 2703
    门限 25A → 2310 mV → DAC 码 2866
    门限 30A → 2442 mV → DAC 码 3030

⚠ 上限提醒：2442 mV 已逼近 ADC 满量程 2500mV（VREFBUF 2.5V）。DAC 满量程是
   3300mV，物理上可以写到 3300mV，但那对应 62A，超过 CC6920 量程与整机
   30A 设计上限。代码里已加钳位，不会让用户调到无效区间。

六、DAC 已确定的技术参量（无需再确认）
================================================================================
  分辨率      12 位，满码 4095
              依据 Drivers/.../stm32h7xx_hal_dac.h:448
                    IS_DAC_DATA(DATA)  ((DATA) <= 0xFFF0UL)
  参考电压    VDDA = 3.3V（H7B0 无独立 DAC 参考脚）
              V_DAC = VDDA × DOR / 4095   →   1 LSB = 0.806 mV
  与 ADC 不同  ADC 用 VREFBUF 2.5V，DAC 用 VDDA 3.3V，两者不可混用
  转换式      DAC_code = mV / 3300 × 4095
  输出配置    缓冲关闭 + DAC_CHIPCONNECT_INTERNAL（喂 COMP 的正确组合，
              见 dac.c:56-57；HAL 明确要求 buffer disable 时不能用
              DAC_CHIPCONNECT_BOTH）
  写入顺序    遵循 errata 2.8.1：先写 DHR 数据寄存器，再设 MODE 字段
  API 签名    HAL_DAC_SetValue(hdac, Channel, Alignment, Data) —— 4 参数
